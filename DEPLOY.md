# Putting School Unity online (Render + Notch Pay)

This puts School Unity on a public HTTPS address, with schools and parents paying in XAF through Notch Pay
(MTN Mobile Money, Orange Money, card). Allow about 30 minutes.

**Cost:** Render Starter instance (about US$7/month) + 1 GB persistent disk (about US$0.25/month).
Notch Pay charges a fee per successful payment; see their pricing.

## 1. Get the code onto the branch Render will deploy

Render deploys a GitHub branch. Merge this work into `main` (or the branch you want live) first.
`render.yaml` in the repository root tells Render how to run the app.

## 2. Get your Notch Pay keys

1. Create an account at <https://business.notchpay.co>.
2. Open the API keys page (Settings / Developer → API keys) and copy the **sandbox public key**.
   Sandbox payments are simulated, so you can test the whole flow without real money.
3. You'll switch to the **live public key** after Notch Pay has verified your business (step 6).

## 3. Create the service on Render

1. Sign in at <https://dashboard.render.com> with GitHub.
2. **New → Blueprint**, pick the `school-unity` repository and the branch from step 1.
3. Render reads `render.yaml` and asks for three values:

   | Variable | What to enter |
   |---|---|
   | `OWNER_EMAIL` | Your email: the platform owner login (the SaaS operator, not a school) |
   | `OWNER_PASSWORD` | A strong password, at least 10 characters |
   | `NOTCHPAY_PUBLIC_KEY` | The sandbox public key from step 2 |

4. Click **Apply**. The first deploy takes a few minutes. Render shows the address,
   e.g. `https://school-unity-abcd.onrender.com`.

`SESSION_SECRET` is generated for you. The database lives on the persistent disk at `/var/data`,
so data survives deploys and restarts. Render keeps daily snapshots of the disk.

## 4. Tell Notch Pay where to send payment notifications

In the Notch Pay dashboard, add a webhook with the URL

```
https://<your-render-address>/webhooks/notchpay
```

The payer is normally sent straight back to School Unity after paying. The webhook also records payments
when the payer closes the browser early. School Unity never trusts the webhook's content: it asks
Notch Pay's API for the payment's real status before crediting anything.

## 5. Check it works (sandbox)

1. Open your Render address and sign in with `OWNER_EMAIL` / `OWNER_PASSWORD`. You land on the platform console.
   Under **Plans**, set your monthly prices (defaults: Starter free, Growth 25,000 XAF, Enterprise 75,000 XAF).
2. Open the site in a private window and **Register your school**. Currency defaults to XAF.
3. As that school's admin: add a class, a student with a portal login (**Students → Add → Create login**),
   and a fee item (**Fees & payments**).
4. Sign in as the student → **Fees → Pay now**. Complete the sandbox payment on Notch Pay with a test number:
   MTN `+237670000000` (succeeds), Orange `+237690000000` (succeeds), `+237670000002` (fails),
   `+237670000004` (cancelled by the payer). You return to School Unity, the payment appears on the student's
   statement, and the admin sees it under **Payment history**.
5. As the school admin: **Plan & billing → Upgrade to Growth** and pay. The plan switches and shows
   "paid until" 30 days ahead.

## 6. Go live

When Notch Pay has approved your business, replace the key in Render:
**school-unity → Environment → `NOTCHPAY_PUBLIC_KEY`** → live public key → **Save** (Render redeploys).
Make one small real payment to confirm.

## Optional

- **Your own domain:** Render → school-unity → Settings → Custom Domains. Then add an environment variable
  `PUBLIC_URL=https://your-domain` so payment return links use it, and update the Notch Pay webhook URL.
- **Back up the database:** Render → school-unity → Shell, then download `/var/data/school-unity.db`, or rely on
  Render's disk snapshots.

## Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `NODE_ENV` | yes | `production` (set by render.yaml) |
| `SESSION_SECRET` | yes | Signs login cookies (generated by render.yaml) |
| `DB_FILE` | yes | Database path on the persistent disk (set by render.yaml) |
| `OWNER_EMAIL`, `OWNER_PASSWORD` | first start | Create the platform owner account on an empty database |
| `NOTCHPAY_PUBLIC_KEY` | for payments | Notch Pay public key. Without it, online fee payments and paid plan upgrades are off |
| `PUBLIC_URL` | no | Public address for payment links; defaults to Render's address |
| `DEFAULT_CURRENCY` | no | Currency for new schools (default `XAF`) |
| `PLATFORM_CURRENCY` | no | Currency plans are charged in (default `XAF`) |

## Things to know

- **One instance only.** SQLite on a disk serves one instance; don't scale the service beyond 1.
  That is plenty for many schools. Moving to PostgreSQL is the path for very large deployments.
- **Plan expiry is reminder-only.** When a paid plan or trial runs out, school admins see a renewal reminder
  on every page, but nothing is locked. As the platform owner you can suspend a school, change its plan,
  or set its "paid until" date by hand (for cash or bank payments) under **Schools**.
